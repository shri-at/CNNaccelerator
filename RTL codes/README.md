## RTL Module Description

This repository contains the final synthesizable RTL implementation of a reconfigurable CNN accelerator datapath. The design consists of three main hardware modules: a Partial Feature Map Producer (PFPM) and two dense layer variants.

---

### Partial Feature Map Producer (PFPM)

The PFPM module acts as the core computational block of the convolutional layer. It performs valid cross-correlation between the input feature map and a set of kernels to generate partial feature maps. Partial feature maps corresponding to all input depths are accumulated along with the bias matrix to produce the final feature map.

The PFPM module is designed to be reusable. Depending on system requirements, the same hardware can be reused across convolution layers using an external controller, or the module can be re-instantiated to increase parallelism. This enables flexibility in designing CNN architectures with different depth and throughput requirements.

The PFPM datapath is fully pipelined, allowing one output to be produced per cycle after pipeline fill.

---

### Dense Layer Modules

Two dense layer modules are provided:

- A dense layer with Leaky ReLU activation
- A final dense layer with argmax activation for classification

The dense layers operate on flattened feature maps generated by the convolution stage. Each output is computed using weighted summation followed by bias addition.

Both dense layer modules incorporate batch processing, where outputs are computed in configurable batches. The batch size determines the latency–area trade-off, allowing the designer to choose between higher parallelism or lower hardware utilization based on system constraints.

---

### Fixed-Point Representation

All computations use signed Q1.15 fixed-point arithmetic. This format provides sufficient numerical precision for CNN workloads while significantly reducing hardware complexity compared to floating-point implementations. Intermediate results are appropriately shifted and clamped to prevent overflow.

---

### Design Characteristics

- Fully pipelined datapaths for improved throughput
- Batch processing support in dense layers for latency–area trade-offs
- Reusable and re-instantiable PFPM architecture
- Parameterizable dimensions such as input size, output size, and batch size
- Written entirely in synthesizable Verilog
